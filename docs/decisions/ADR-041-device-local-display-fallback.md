# ADR-041 — backend 침묵 시 기기가 로컬 상태로 표시한다 (표시 축 fallback 허용)

- 상태: 채택
- 결정일: 2026-10-17
- 결정자: 사용자 (세션 질문 "왜 계속 안 되는거야"에 대한 답으로 R1 선택)

## 배경

알림/표시 한 번이 사용자에게 도달하려면 **6개 링크가 직렬로** 전부 성공해야 한다:

```
① device가 trip 등록 → ② backend가 KV에 보관 → ③ LA push 토큰 등록
   → ④ 게이트 통과 → ⑤ cron 발사 → ⑥ 기기/위젯 렌더
```

각 링크가 단일 실패점이고, **어느 하나가 끊기면 사용자 화면은 전면 침묵**한다. 2026-10-15 하루에 서로 다른 4개 링크가 끊긴 것이 실측됐다:

| 끊긴 링크 | 실측 |
| --- | --- |
| ② 좀비 트립 2시간 생존 | `trip-end {reason:"expired"}` — KV write 쿼터 60~72% 소모 |
| ① TTL 만료 후 재등록 | `POST /trips` **400 × 30** (#2999, fix 배포됨) |
| ② 생성 6초 후 DELETE | `trip-end {reason:"user-delete"}` — 주체 미확정 |
| ①②③ KV 쿼터 고갈 | `POST /position` **500 × 63**, 2시간 회복 0 (#3006, 코드 10048 프로브 확인) |
| ④ 역만 탭한 사용자 | `lockless-no-user-intent=79` — 알림·LA 둘 다 침묵 (#2997) |

**매 라이드가 다른 링크에서 죽었다.** 세션마다 한 링크를 고쳤고 다음 라이드는 다른 링크에서 끊겼다 — `lesson_tactical_fix_whack_a_mole_systemic`이 기록한 패턴의 구조적 원인이 여기다.

## 이 ADR이 수정·대체·모순하는 결정

| 결정 | 어느 축을 어떻게 재배정하는가 |
| --- | --- |
| **2026-09-03 확정 아키텍처** (`memory/decision_ARCHITECTURE_COMMITTED_server_track_visible_push.md`) — *"backend추적→LA표시, device=탭만"*, 폐기 목록에 **device 추적·발사·location** 포함, *"재litigate 금지"* | **표시 축만 재배정한다.** backend가 **침묵할 때** 기기가 자신의 로컬 상태(fusion 현재역/route/lock)로 **표시**할 수 있다. 그 메모리의 "재litigate 금지"는 본 ADR로 **표시 축에 한해 해제**된다 — 2026-10-15 실측이 "단일 권위 = 단일 실패점 = 전면 침묵"을 확정했기 때문이다. |
| 같은 결정의 **발사 축** | **유지(불변).** 알림/푸시 발사 권위는 계속 backend 단독이다. 기기가 다시 발사하기 시작하면 ADR-035/036/040이 수렴시킨 "단일 발사 권위"가 깨지고 중복·유령 알림 회귀가 돌아온다. **이 ADR은 발사를 허용하지 않는다.** |
| **#2498** *"backend push가 LA content의 유일한 저자"* | **조건부 수정.** backend push가 **도달하는 동안에는** 그대로 단독 저자다(heartbeat가 기기 값을 덮으므로 경합도 없다). backend 침묵이 **판정된 구간에서만** 기기가 로컬 값으로 표시한다. |
| **ADR-039** (GPS 권위 경계) / `memory/feedback_no_gps_for_decision` — *"GPS는 결정 권한 없음(지상만)"* | **유지.** 로컬 표시는 **결정이 아니라 표시**다. GPS/fusion 값으로 알람을 **쏘지 않는다**. 표시에 쓰는 값의 신뢰도 등급은 ADR-039의 tier를 그대로 따르고, 낮은 tier는 "추적 정확도 저하"로 **표시에 명시**한다. |

## 결정

1. **표시 축 fallback 허용** — backend 침묵이 판정되면 기기는 로컬 상태로 현재역/경로/상태를 계속 표시한다. 사용자가 "앱이 죽었다"고 느끼는 전면 침묵을 없앤다.
2. **발사 축은 건드리지 않는다** — 로컬 표시는 알림을 쏘지 않는다.
3. **침묵 판정은 기존 신호를 재사용한다** — 새 신호 금지. 후보: `/position` 응답의 `degraded`(#3006 D, 이미 배선) · `lastSilentPushReceivedAt` 공백 · LA push 미수신. 어느 것을 쓸지는 착수 PR에서 확정하고 **plan 검증을 거친다**.
4. **표시에는 출처를 밝힌다** — 로컬 표시 구간임을 사용자가 알 수 있어야 한다(`memory/decision_notification_priority_3tier`의 ambient 등급 = 상태줄 표시). #2997 S4-b의 "멀어서 추적 안 됨"과 같은 표면을 쓴다.

## 대안 (기각)

| 대안 | 기각 이유 |
| --- | --- |
| 유료 전환만 하고 구조는 유지 | 쿼터 천장은 제거되지만 **다른 5개 링크의 단일 실패점은 그대로**다. 2026-10-15의 4개 실패 중 쿼터는 하나였다. |
| 기기 발사 권위 복원 | ADR-035/036/040이 수렴시킨 단일 발사 권위를 깨뜨린다 — 중복/유령 알림 회귀. 사용자가 겪은 침묵은 **표시** 문제이고 발사까지 되돌릴 근거가 없다. |
| 사슬을 짧게 재설계 | 옳지만 범위가 크다. 본 ADR은 **전면 침묵만 먼저 끊는다**. |

## 결과

- 사용자: backend 장애 중에도 현재역/경로가 보인다. 알림은 안 올 수 있고 그 사실이 표시된다.
- 개발: 표시 경로가 2개(backend push / 로컬)가 되므로 **어느 쪽이 그렸는지 관측 가능해야 한다** — 표시 출처를 덤프/D1에 남긴다(`lesson_channel_dual_role_severed_on_redesign` 재발 방지).

## 리스크

- **이중 저자 경합** — backend가 돌아왔을 때 로컬 표시가 남아 stale을 그릴 수 있다. heartbeat(90s)가 content-state를 통째로 교체하므로 구조적으로는 backend가 이기지만, "침묵 판정 → 복귀" 전이를 테스트로 고정해야 한다.
- **침묵 오판** — 짧은 네트워크 끊김을 침묵으로 보면 불필요하게 로컬로 떨어진다. 판정 임계는 기존 상수(예: `SIGNAL_4_SILENT_PUSH_TIMEOUT_MS` 30분)를 재사용해 보수적으로 둔다.
- **범위 침범** — "표시만"이라는 경계가 느슨해지면 기기 발사로 번진다. 착수 PR의 acceptance에 **"알림 발사 0건"을 assert**로 박는다.
