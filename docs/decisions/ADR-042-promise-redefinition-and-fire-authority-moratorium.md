# ADR-042: 서비스 약속 재정의 + 발사 권위 모라토리엄

- **상태**: **Accepted** (2026-10-19 작성, 같은 날 사용자 승인 — 결정 1·2 모두)
- **작성 배경**: 2026-10-19 독립 진단 2건(신선 컨텍스트 에이전트, 1차 사료 기반·상호 무인지)이 "수개월 수렴 실패"의 구조적 원인에 수렴. 사용자 지시: "문서로 고정".

## 컨텍스트 — 수렴 실패의 정량 정의

- **D1 `trip_metrics` 실측 (4.5개월, 117 트립): `chain_complete` = 8건 (6.8%).** 정의는 `d1TripMetrics.ts:300-302` — 트립 종료 시점에 ①탑승 프롬프트 발사됨 ②boarding lock 성립, **둘 다**. 이 둘 없이는 매역/환승/하차 안내가 원리적으로 작동 불가하므로, 92%의 트립에서 핵심 서비스가 시작되지 못했다. (caveat: 6~8월분은 #2628 계측 결함 이전이라 과소측정 가능. 이 기준은 "목적지 완주"보다 낮은 문턱 — 전체 경험 성공률은 이보다 낮다.)
- 불만 가족 7개 전부 최초 라이드(6/24)에 등장, 10월까지 전부 재발 — 완전 해소 0.
- 두 진단의 수렴 원인 상위: ① 목표↔신호 물리 간극(arvlCd 도착창 ~30s < cron 60s 양자화 — `scheduled.ts:3856` 자인 / iOS BG suspend 25분 #2306 / 지하 GPS 무결정권) 위에 결정론적 약속을 세우고 간극을 코드로 메움(scheduled.ts 4개월 2.5배, 9,106줄) ② 발사 권위 4개월 4회 반전(ADR-026→032→031→033/035/036→040→041), 그중 033/035/036 라인은 `EXPO_PUBLIC_MINIMAL_ALARM` 미설정으로 **한 번도 켜지지 않은 채** 머지·close됐고, 전환 근거 실측(#2122 "push 지연 35~51s")은 10/9 재실측(1~2s)으로 소멸 ③ 검증 자산이 부품 단위(whole/replay 파일 7~8%, jest.mock 994회).
- 기각된 가설: 노력 배분 오류(churn top 40이 전부 핵심 루프), 프로세스 게이트 부재(각 패치는 프로세스 체크를 전부 통과하며 재발).

## 결정 1 — 서비스 약속을 신호가 보장 가능한 단위로 재정의

#912 epic의 "매역 도착 **순간** 알림 100%"를 폐기하고 다음으로 대체한다:

| 채널 | 새 약속 | 근거 신호 |
| --- | --- | --- |
| 탑승 질문(프롬프트+LA 배너) | **열차 도착 확정 시에만** 발사(화면+소리). 도착 확정된 새 열차마다 즉시 1회, 간격 하한 없음(2026-10-19 사용자 결정, #3057 코멘트) | realtimePosition trainSttus(DEPARTED ~2분 지속 — 양자화 면역) + arvlCd {1,2} |
| 매역 알림 | "도착 순간"이 아니라 **해당 역 재차 중 ~ 늦어도 다음 역 도착 전** | 사용자 허용오차 원문(6월, verbatim 로그 99행 "약 1정거장까지 기다릴 예정") |
| 틀린 열차 lock 금지 | 불변 (ADR-010: miss와 동급) | — |

acceptance 측정: `chain_complete`(발사 성립) + 배포 후 D1에서 매역 발사 시각이 새 약속 창 내인 비율. "도착 순간" 기준의 지각 이슈는 더 이상 결함으로 접수하지 않는다(새 약속 창 밖만 결함).

## 결정 2 — 발사 권위 모라토리엄 + 죽은 경로 물리 철거

1. 발사 권위는 **ADR-041 상태로 고정**(backend 발사 권위 + 규정된 device 표시 fallback). 추가 재배정 금지.
2. 모라토리엄 해제 조건: ① 프로덕션 2주 실측(새 약속 기준 결함률) ② 재배정 근거 실측의 **독립 재검증**(#2122 교훈: 틀린 측정 위 6주 전환 재발 방지) ③ 사용자 승인.
3. **"전환 완료"의 정의를 신설**: 구 경로의 코드 물리 삭제 + 그 경로의 로그/KV write 0 확인. ADR-040이 확인한 "죽은 경로가 로그를 계속 생성해 살아있는 경로 수를 코드로 알 수 없음" 상태의 해소가 convergence-phase2(plan-2026-10-18-convergence-phase2.md)의 완료 조건이다.
