# ADR-048 — 취침 알람 "N역 전부터": 칸·방식·leg 단위

- 상태: Proposed (2026-10-24)
- 관련: #3100, ADR-024, ADR-023, ADR-041, ADR-042, `tasks/plan-2026-10-24-3100-minimal.md`
- 번호 배정: 043 lock-only 초안, 044 S1, 045 KV 절감, 046 device-departure-memory, 047 trip-instance-identity가 계획에서 예약돼 있어 048을 쓴다.

---

## 배경

취침 알람은 현재 환승역·하차역 "1개 역 전" 한 번뿐이다(ADR-024 스펙 표). 사용자 요구(2026-10-20, 2026-10-23, #3100):

> "취침모드에서 최대 3개역 전부터 알람이나 알림이 올 수 있도록 하자. 1~3개역 전에 알람 알림을 선택할 수 있고 …"
> "2역이면 두개 역 다 울리는 것이고, 1개역 3개역이면 그 환승 또는 하차 역 n 역 전 부터 매 역 울리는 것임."
> "이거는 설정탭에서 진행하는 것이고 ui 는 단어 글 만 바꾸면 되는거잖아"
> "알림과 알람은 겹쳐도 아무 문제가 없어"
> "용마산 -> 건대 -> 뚝섬 일 때 3개 역전이면, 건대 부터 건대 알람자체가 2개가 되고 … leg-1부터 알람을 가져오지 말고 leg-2부터 3개역 전이라도 그냥 2개역전부터 울릴 수있도록"
> "매역 알람, 선택한 역에서만 알람 체크 박스도 만들자"
> D-1 (10/23): 구간 출발역 알람(짧은 leg에서 출발역/환승역이 'N역 전' 범위에 들어가는 경우)은 그 leg 열차가 출발역을 떠난 것이 확인된 뒤 울린다(탑승 확인 즉시 X — #2688 40초 오발사 방지). 기본값 사용자(1역 전)는 출발역 알람을 적용하지 않아 현행과 동일.
> D-2 (10/23): "취침모드에서 알림은 없어도 돼" -> 설정에서 알림 열 삭제, 알람만 N역 전부터 선택(행 = N역 전, 발사 방식 = 매 역 / 선택한 역에서만). 취침 트립의 매역 알림은 현행 그대로.

## 이 ADR이 수정·대체·모순하는 결정

- **ADR-024 스펙 표 `발사 시점` 행(§결정 1, 알람 열 "환승역/도착역 1개 역 전")**: "1개 역 전 고정"을 **(방식, 칸 집합 {N}) 설정**으로 재배정한다. 기본값은 `{선택한 역에서만, {1역 전}}`이라 기본 사용자의 발사 시점·키·문구·wire는 바이트 동일하다(PR-1 golden). 알림 열(매역 알림)의 **설정 UI**는 D-2로 삭제하되, 알림 열의 **취침 mute 범위는 아래 개정(2026-10-25)으로 intermediate 한정으로 축소**한다(ADR-024 `:29` 재배정, 이 절 마지막 항목 참조).
- **ADR-024 스펙 표 `제약` 행("1역 전 = 출발역이면 발사 금지")**: 기본값에서는 그대로 유지한다. **비기본 설정에서만** "leg 길이가 N 이하인 칸"을 허용하되 그 leg 열차가 출발역을 **떠난 것이 확인된 뒤**에 발사하도록 재정의한다(D-1; 구현은 PR-6, 그 전에는 해당 칸이 울리지 않을 뿐 오발사 없음). 즉 금지 → "출발 미확인 시 금지, 출발 확인 후 허용"으로 재배정한다.
- **ADR-023 "Backend는 취침 무관 발사" / `sleepModeEnabled` monitoring 전용**: 취침 알람 발사 게이트(`evaluateSleepAlarmTrigger`)가 이미 `trip.sleepModeEnabled === true`를 읽는다(#2066 이후). 본 ADR은 이 현실을 인정해 `types.ts` 주석을 정정했고, 새 설정 `Trip.sleepAlarm`도 취침 ON일 때만 읽는다. **매역 push 경로의 취침 분기는 intermediate 매역 mute 하나뿐이다**(2026-10-25 개정: 환승·하차 도착 `station-` push는 취침 무관 발사. ADR-023 첫 원칙은 환승·하차 도착에 한해 복원). 취침 알람 경로의 backend 소유는 ADR-024가 이미 정한 "원격 visible 주 채널"의 연장이다.
- **ADR-041 결정 2 / ADR-042 결정 2.1 (발사 권위 불변)**: 재배정 없음. 발사 주체는 backend cron(원격 visible alert + companion) 그대로이고, 기기 로컬은 새 알림을 쏘지 않는다. 기기 변경(PR-3/4)은 표시·fired 키·dedup·안전망 칸에 한정된다.
- **ADR-040(매역 알림 단일 발사)**: 취침 알람 collapse-id는 칸마다 분리(`alarm-s{N}-…`)되나 매역 알림 collapse 규칙(`station-…`)은 건드리지 않는다.
- **ADR-024 스펙 표 `모드` 행 알림 열("취침모드 mute (backend 분기)", `:29`) — 개정 2026-10-25**: 취침 mute 축을 "취침 trip의 모든 매역 알림"에서 **"취침 trip의 intermediate 매역 알림"으로 축소**한다. 취침 lock trip의 환승·하차 도착 `station-` push는 mute하지 않고 비취침과 같은 코드·게이트·payload(`station-` collapse, `alarm.wav`, `time-sensitive`)로 발사한다(2026-10-25 사용자 결정; 근거: CLOSED #2363 acceptance — 취침 환승·도착 = loud wake). 구현: `fireArvlCdStationPush`·`fireVanishFallbackStationPush`·`runMidCycleFireOnly`의 취침 mute 조건을 `sleepModeEnabled === true && waypoint.kind === 'intermediate'`로 좁힌다. `fireSyncSkippedStationPasses`는 비취침도 intermediate만 발사하므로 변경 없음. 문구는 변경 없음(별도 결정). 한계: 앱이 화면에 켜진 상태(FG)에서는 원격 alert가 무음(비취침과 동일한 기존 동작), 환승역에서 hop-end 프롬프트 소리와 겹침(비취침 현행과 동일), 취침 trip은 직전 intermediate mute 때문에 cross-station 45초 dedup 창이 갱신되지 않아 비취침이 dedup으로 건너뛰는 환승·하차를 취침은 발사할 수 있다(의도로 수용). 취침 N역 전 알람(`alarm-` collapse)과는 키·collapse가 달라 서로 막지 않는다.
- 확인한 결정 목록: ADR-023, ADR-024, ADR-040, ADR-041, ADR-042, `tasks/` lock-only 초안(번호 미확정, 아직 docs/decisions에 없음; "lock 활성 취침 trip의 N역 전으로 범위 한정"과 정합 — 모든 발사는 lock 게이트 뒤).

## 결정

1. **칸**: 행 = "N역 전"(N은 최소 1 ~ 최대치). 최대치는 코드 상수 한 곳(`SLEEP_ALARM_MAX_STOPS_BEFORE`)에서만 파생하며 UI 행 수·검증 범위·칸 판정이 함께 따라간다(1·2·3 리터럴 금지, 가드 테스트로 강제).
2. **방식**: `매 역`(시작 N부터 도착 직전까지 매 역) / `선택한 역에서만`(체크한 칸에서 1회). 기본값 = 선택한 역에서만 + 1역 전.
3. **leg 단위**: 남은 정거장은 타깃이 속한 leg 안에서만 센다. 앞 leg의 역은 세지 않는다(용마산→건대입구→뚝섬, 3역 전: leg-2는 2역 전부터).
4. **알림 열 삭제**: 알람만 설정한다. 같은 역에서 취침 알림과 알람이 겹쳐도 둘 다 발사한다.
5. **출발역 칸(PR-6)**: 비기본 설정에서 leg 길이 ≤ N인 칸은 출발 확인 뒤 발사. 기본값은 적용하지 않는다.
6. **기본값 불변**: 설정이 없거나 기본값과 같으면 payload·hash·dedup 키·collapse-id·문구·KV 호출 수·D1 행이 현행과 바이트 동일하다.
7. **점프 처리**: 한 번의 전진/소비가 여러 칸을 건너뛰면 1회(catch-up)로 합치고 문구는 실제 남은 정거장 수를 쓴다.
8. **관측**: 비기본 칸의 fired / rolled-back만 D1 `trip_events kind='sleep-alarm'`에 1행(기본 칸은 행 0).

## 대안 (기각)

- 최대치 3 하드코딩 / UI 3행 고정: 요구가 "최대 3"이지만 확장 가능해야 한다는 글로벌 규칙(하드코딩 금지)과 사용자 재지시에 위배. 상수 파생 + MAX=4 변형 테스트로 대체.
- 알림·알람 3x2 매트릭스(10/20 스펙): D-2로 철회(알림 열 삭제).
- leg 경계를 넘어 앞 leg부터 센다: 사용자가 명시 거부(leg-1부터 가져오지 말 것).
- 출발역 칸을 탑승 확인 즉시 발사: #2688 40초 오발사 재발. 출발 확인 뒤로 지연(D-1).
- 정확성 게이트 보강 없이 기기 로컬에서 N칸 발사: 발사 권위 재배정이라 ADR-041/042 모라토리엄에 위배.

## 결과

- 설정 탭(PR-5 이후)에서 N역 전·방식을 고를 수 있다. 기본 사용자는 변화 없음.
- backend는 비기본 설정 trip에 한해 칸당 KV get+put(+실패 시 delete) 1쌍이 늘고, 기본값은 증가 0.
- 순서: PR-1(cron 발사) 배포 후에도 비기본 사용자는 PR-4(기기 송신) 전까지 없다.

## 리스크

- 짧은 leg 칸은 PR-6 전까지 울리지 않는다(miss, 오발사 아님). 출발 신호가 샘플링 간격에 안 잡히면 "출발 시점"이 아니라 "첫 역 도착 시점"에 울릴 수 있다(트립 173 실측: `arvlCd=3` 행 0건).
- sync 경로(PR-2)·기기 ledger/안전망 칸 구분(PR-3/4)이 뒤따르기 전에는 해당 경로가 기본 칸만 다룬다.
- lockless 가짜 전진(#3083)이 칸을 lock 이전에 소비하면 그 칸은 울리지 않는다("lock 없음 = 알림 없음", miss만 남음).
