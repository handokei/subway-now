# 13. 운행 안내 (사고 · 공사 · 지연)

## 책임
지하철 운행 차질 정보(사고·공사·지연)를 외부 API에서 받아 사용자에게 노출하고, 본인 경로에 영향이 있으면 능동적으로 알린다.

## 경계
- 정상 운행 상황의 경로 탐색은 [03-destination-route.md](./03-destination-route.md).
- 알람 발사 채널 자체는 [06-alarm.md](./06-alarm.md) / [07-notice.md](./07-notice.md).

---

## 기본 동작

- 사용자는 현재탭/지도에 **운행 차질 배지/공지**를 볼 수 있다. (정상 시 표시 0)
- 사용자는 배지를 탭하면 상세 내역(영향 노선·구간·예상 복구 시각)을 볼 수 있다.
- 사용자는 자신의 **현재 경로에 영향 있는 차질**이 있으면 자동 푸시를 받을 수 있다.
- 사용자는 차질 발생 시 **대안 경로**를 자동 제안받을 수 있다.
- 사용자는 차질 정보가 일정 주기로 자동 갱신됨을 보장받는다.

## 예외 / 경계 조건

- 사용자는 영향 없는 차질(다른 노선의 사소한 지연)은 푸시로 받지 않는다. (false positive 방지)
- 사용자는 같은 차질에 대해 한 번만 푸시를 받는다. (event 단위 dedup)
- 사용자는 차질이 복구된 시점에 "복구됨" 알림을 받을 수 있다.
- 사용자는 인터넷이 끊겨도 마지막으로 받은 차질 정보를 stale 표시와 함께 볼 수 있다.
- 사용자는 운행 종료 시간(막차) 정보와 막차 임박 안내를 받을 수 있다.

---

## 횡단 의존

- **경로 탐색**: 차질 정보를 경로 후보 필터링에 반영. → [03-destination-route.md](./03-destination-route.md)
- **알람/알림**: 차질 푸시는 알림(Notice) 카테고리. → [07-notice.md](./07-notice.md)
- **오프라인**: stale 표시 적용. → [12-cross-cutting.md](./12-cross-cutting.md)

## 코드 진입점

- ⚠️ 미구현 — 신규 슬라이스 필요 (`src/features/service-status/` 권장)
- 현재 사용 중인 외부 API (참고): `realtimeStationArrival` (도착, `arrivalApi.ts:106`), `realtimePosition` (열차 위치, `backend/alarm-worker/src/seoul.ts:90`). **운행 차질 관련 API는 사용 흔적 없음** (grep 결과 "lineStatus"·"serviceStatus"·"incident"·"공사"·"차질" 키워드 전무).

## 알려진 한계

- ⚠️ **전체 미구현**. API 호출·매칭 로직·UI·푸시 전부 새로 개발 필요.
- ⚠️ "내 경로 영향 판단" 알고리즘 정의 필요 — 어느 정도의 차질을 푸시할지 기준선.
- ⚠️ 막차 임박 안내는 운행 시간표 API와 연계 필요. 별도 confirm 필요.
- ⚠️ **서울 공공데이터 광장의 "지하철 운행 정보" API 카탈로그 존재 여부**는 코드만으로 확인 불가. 외부 카탈로그 조사 별도 작업.
