# 0. 내가 틀렸던 것들 (정정 이력)

측정 없이 **다섯 번** 틀렸다. 그래서 이 plan의 모든 수치는 실데이터 계산값이다.

| 주장 | 실제 |
| --- | --- |
| "폴백 상수가 없다 → 0이면 간선이 공짜" | **틀림.** `getStopSeconds`(`stationRoute.ts:33-45`) 3단 폴백 정상 |
| "미스 시 120초로 바로 떨어진다" | **틀림.** 2단이 `거리÷노선속도`. 내가 "M-1으로 하자"던 것이 **이미 구현됨** |
| "1호선 85%가 120초 폴백" | **틀림.** 1호선 120초는 **6건**, 전체도 14.0% |
| "정차시간은 근거를 만들 수 없다(60초 해상도)" | **틀림.** 시각표가 **`HH:MM:SS` 초 단위** — 정차 **39만 건 실측** |
| "공식이 분 단위라 기존 490건 덮으면 해상도 손실" | **틀림.** 초 단위라 손실 없음. 오히려 **커버리지 2.2배** |

(포털 메타데이터가 "HH:MM, 초 단위 없음"이라 적어둔 것도 **실데이터와 달랐다** — 메타데이터를 근거로 쓰지 않는다.)

# 1. 측정된 현황

## 1-1. 폴백 3단 분포 — 인접 방향쌍 1,040개 전수 (measured)

```
getStopSeconds(line, fromId, toId)      stationRoute.ts:33-45
  1) stationTravelTimes[key]              490 (47.1%)   실측 60~270s
  2) stationDistances[key] → 거리÷속도     404 (38.8%)   lineSpeeds.ts, 표정속도(정차 포함)
  3) STOP_FALLBACK_SECONDS = 120          146 (14.0%)
```

**120초 상수 발동 146건**: 9호선 74 · 공항철도 24 · 경의중앙 18 · 4호선 12 · 1호선 6 · 2호선 4 · 분당 4 · 3호선 2 · 7호선 2

## 1-2. 🔴 계통 오차 확정 — tier 1에 정차시간이 빠져 있다 (measured, 303건 대조)

시각표에서 구간을 두 방식으로 산출해 우리 `stationTravelTimes`와 대조했다:

```
순수주행  = 다음역 도착 − 현재역 출발
도착간격  = 다음역 도착 − 현재역 도착   (= 순수주행 + 현재역 정차)

우리값 − 순수주행:  중앙값 +0초   평균 +0.4초     ← 일치
우리값 − 도착간격:  중앙값 −30초  평균 −30.1초    ← 30초 부족
```

**우리 tier 1은 순수 주행시간이다. 정차시간 30초가 빠져 있다.**

그런데 `buildRouteGraph.ts:44`는 간선 가중치를 **"정차 시간 포함 표정속도"** 로 전제한다(confirmed). **전제와 데이터가 어긋난다.**

| 여정 | 누락 |
| --- | --- |
| 5역 | 2분 |
| 10역 | 4.5분 |
| **15역** | **7분** |
| 20역 | 9.5분 |

**역 수에 선형 비례해 누적**된다. 10/9 트립(군자→광화문, 11역)이면 약 5분 과소추정.

**주의 — 이중 가산 금지**: tier 2(표정속도)는 **이미 정차 포함**이다(`lineSpeeds.ts:4` "정차 시간 포함 평균"). tier 1에만 가산해야 한다.
