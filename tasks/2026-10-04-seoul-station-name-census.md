## 🔴 요구사항 (2026-10-10 사용자 지시) — 괄호 부기는 **표시에서 유지**한다

> "올림픽공원(한국체대) () 표시 있는건 ()도 함께 표시할 수 있도록"

**사용자에게 보이는 모든 지점에서 괄호 부기를 떼지 않는다.** `올림픽공원(한국체대)`은 `올림픽공원`으로 축약하지 않는다.

### 현재 상태 (measured 2026-10-10)

### 지켜야 하는 경계 — 매칭용 ↔ 표시용 분리

| 용도 | 괄호 | 이유 |
| --- | --- | --- |
| **표시**(알림·LA·위젯·탭 리스트·경로 화면) | **유지** | 본 요구사항. 사용자가 역을 식별하는 단서다 |
| **Seoul API 질의/매칭** | 역별 매핑 데이터로 변환 | 평명이 정식인 역 32개 존재(아래 표). 다만 **괄호명이 정식인 역 19개**도 있어 일괄 제거는 금지 |

**혼동 금지**: 위 "평명이 정식 질의명 32개"는 **API 질의 문자열**에 대한 것이고 **표시 문자열이 아니다.** 질의용 축약을 표시에 재사용하면 요구사항 위반이다.

### 외부 데이터 매칭 시 주의 (2026-10-10 신규)

경로 소요시간 트랙(`plan-2026-10-10-route-traveltime-accuracy.md`)에서 외부 CSV를 받으며 **같은 역의 표기가 소스별로 다름**을 확인했다:

| 소스 | 표기 |
| --- | --- |
| 국가철도공단 9호선 역간거리 CSV | `올림픽공원(한국체대)` |
| 서울교통공사 열차운행시각표 CSV | `올림픽공원` |
| `stations.json` | `올림픽공원(한국체대)` |

→ 외부 데이터를 흡수할 때 **매칭은 정규화해서 하되, `stations.json`의 표기(괄호 포함)를 SSoT로 유지**한다. 외부 소스의 평명으로 우리 데이터를 **덮지 않는다.** `#1472`의 "stations.json에 entry 없으면 skip + 로깅" 정책과 같은 방향이다.

## position statnNm 추가 함정 (B 범위에 포함할 것)

R2 캡처 어휘 대조에서 발견 — `parsePositionEntry`(seoul.ts:308)는 statnNm을 **무가공 통과**시키는데 Seoul position 피드는 역명 아닌 sentinel을 넣는 경우가 있다:

- `성수종착` — 종착 진입 열차의 statnNm (10/3 열차 3174 실측). `segmentStations.indexOf()` 영구 불일치.
- `성수지선` — 지선 진입 표기.
- 기존 트리머 `parseTerminusStationName`(seoul.ts:275~)은 trainLineNm 전용 — statnNm 경로엔 미적용.

## 미해결 (별도)

- 2호선 지선역(용답·신답·용두·도림천·양천구청·신정네거리)·7호선 산곡이 stations.json line 집합에 부재 — 캡처 어휘 대조에서 노출. route가 지선을 지나지 않는 한 무해하나 전수 정합 체크 대상.
