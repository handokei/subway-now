## Root cause 가설

**Primary** — `LOCKLESS_HOP_WINDOW_DEFAULT=1`이 2호선 환승 leg 진입 시(7호선→2호선) 강변 candidate를 `firedAlarms` 기반 inferred hop(7호선 fired 최대 idx 기준)에서 4~8 station 격차로 reject. PR #1917(RC-18 line filter), PR #1906(RC-3 weighted vote), PR #1905(RC-11 route freeze) 모두 station-passed 발사 경로가 아닌 fusion candidate 경로만 보정 → 본 gate에 의해 전부 무력화.

**Secondary** — `boardingListArrivals` 양방향 union fallback(#1326)이 환상선 + `resolveTripDirection`=null 경계에서 noisy. 같은 line(2) 두 방향이 동시 노출 → 사용자 오선택 risk.

**Tertiary** — Backend는 사용자 명시 의향 trip을 `infoModeEnabled=true`로 받지 못해 lockless cron path(L980) 미진입. silent push intermediate=0. + Seoul API outage(self-poll error=4)로 boarding-prompt도 no-candidates 차단.

1. **gate-hop-window 환승 leg 전환 시 window 동적 확장**
