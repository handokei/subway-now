## Root cause 가설 (확률 순)

1. **promptDisplay가 cross-trip 자동 전환 시 갱신 X (확률 95%, 단일 root)**. `buildBoardingPromptContext` 입력 route가 사용자 등록 원 경로(line 7) 그대로 → 새 POST /trips도 line=7/용마산 stamp. backend는 영원히 7호선 용마산 후보 검색 → RC-13 skip / 9단 게이트 차단 → UI 발사 0건.

2. **lockMissing 분기 ≠ lock active**. scheduled.ts:3348~3349 docstring은 "lockMissing 분기에서만 호출"이라 명시. 13:43:23부터 device boardingLock active=yes인데 13:44~13:46 RC-13 로그 3회는 backend가 device → backend lock sync(13:43:29)를 cron이 못 본 race 또는 lockMissing 판정 자체가 다른 분기일 가능성. backend lockMissing 정의/cron 진입 조건 확인 필요.

3. **PR #1918 RC-2 trip-scoped dedup이 cross-trip 전환 시 reset 안 됨 (보조)**. 이전 7호선 leg가 boardingPromptState fired면 dedup 차단 가능. 단 evidence는 RC-13 skip이 먼저라 P3.
